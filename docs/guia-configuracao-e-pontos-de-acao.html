Microled NFS-e — Guia técnico

Onde fica cada configuração, quais propriedades do appsettings o código realmente lê e onde mexer em cada fluxo (Access, impostos, envio, NF, pagamento, tomadores, certificado).

Referente ao código de outubro/2026 (instalação on-prem). Nomes de arquivos relativos a MicroledNF/ (back-end) e MicroledNfFrontEnd/ (front-end).

Arquitetura e portas

Launcher Painel

Microled.Nfe.DesktopLauncher — sobe o PostgreSQL portátil, a API e o agente; grava o caminho do Access.

Front Angular

MicroledNfFrontEnd — no on-prem é servido pela própria API (api\wwwroot) em http://localhost:5249.

API API principal

Microled.Nfe.Service.Api — porta 5249, ambiente OnPrem. Notas, tomadores, pagamento; PostgreSQL DB_NFE (porta 5435).

Agente Agente local

Microled.Nfe.LocalAgent.Api — porta 5278, ambiente Production. Certificado, Access, cálculo, SOAP com a prefeitura.

Por que existe um proxy?

No on-prem o front usa localAgentBaseUrl: "" e chama /api/local/* na própria porta 5249; a API repassa para o agente em 127.0.0.1:5278 (Middleware/LocalAgentProxyExtensions.cs). Na versão em nuvem o front chama o agente direto em http://localhost:5278.

Onde cada configuração é lida

Os arquivos são lidos na ordem abaixo; o último vence, chave por chave (só a chave presente é sobrescrita, o resto continua vindo do arquivo anterior).

API Microled.Nfe.Service.Api

  1. api\appsettings.json
  2. api\appsettings.OnPrem.json (o launcher inicia com ASPNETCORE_ENVIRONMENT=OnPrem)
  3. Variáveis de ambiente definidas pelo launcher: ASPNETCORE_URLS=http://localhost:5249 e ConnectionStrings__NfeDatabase
A connection string do on-prem vem do launcher

O valor de ConnectionStrings:NfeDatabase em appsettings.OnPrem.json é sobrescrito pela variável de ambiente montada pelo launcher (porta/usuário/senha do PostgreSQL portátil). Alterar só o JSON não muda o banco usado.

Agente Microled.Nfe.LocalAgent.Api

  1. agent\appsettings.json
  2. agent\appsettings.Production.json (o agente roda como Production; o arquivo não é distribuído hoje)
  3. agent\appsettings.Client.json (opcional — gerado a partir de appsettings.Client.template.json nos pacotes de cliente)
  4. C:\ProgramData\Microled\Nfe\localagent\settings.json — gravado pelo painel e pela tela de configuração
  5. %LOCALAPPDATA%\Microled\Nfe\localagent\settings.json (opcional, por usuário)
Regra prática

Para mudar algo só nesta máquina, edite o settings.json em ProgramData (sobrevive a reinstalações). Para mudar o padrão de todas as instalações, edite o appsettings.json do projeto e gere um novo instalador.

Alterações de configuração do agente valem após reiniciar o agente (os serviços leem as opções na inicialização).

Front Angular

api\wwwroot\runtime-config.json — no build on-prem é uma cópia de public/runtime-config.onprem.json. Ver runtime-config.json.

Fluxos do sistema — onde mexer

1. Importar RPS do Access Front Agente

  1. Tela Emissão NFSe → Importar lote (/nfse/emissao-nfse/lote) conta e lê os pendentes: GET /api/local/access/pending-rps (Processado = Não).
  2. Completa o tomador pelo cadastro de tomadores (CNPJ do Access → nome/endereço). Sem endereço completo o RPS não é importado e o motivo aparece no log da tela.
  3. Calcula os impostos (fluxo 2).
  4. POST /api/local/rps/queue-pending: gera o XML, cria a nota "A processar" no PostgreSQL, salva o payload em pending-queue, grava BC/PIS/COFINS/IR/CSLL/Valor_liquido no RPS e marca Processado = Sim.
Tela
pages/importacao-lote-rps/importacao-lote-rps-page.ts
Leitura do Access / colunas aceitas
Infra/Repositories/AccessRpsRepository.cs (lista de colunas em GetPendingRpsAsync)
Fila e gravação dos impostos
LocalAgent.Api/Services/LocalRpsProcessingService.cs → QueuePendingAsync; AccessRpsRepository.UpdateTaxValuesAsync
Regras de preenchimento do tomador
pages/emissao-nfse/data/local-clients.storage.ts (mergeTomadorCadastroIntoForm, getTomadorEnderecoPendencias)

2. Cálculo de impostos Agente

  1. POST /api/local/nfse-sp/calculate-taxes com valorServico (> 0), codigoServico (> 0), aliquotaIss (0–1) e regimeTributario (SimplesNacional | LucroPresumido | LucroReal).
  2. Lucro Presumido / Simples: alíquotas padrão de retenção (PIS 0,65%, COFINS 3%, CSLL 1%, IR 1,5%). Lucro Real: usa as alíquotas enviadas.
  3. Resposta: bases, valores retidos, valorLiquido e a memória de cálculo.
Regras
Application/Services/NfseSpTaxCalculationService.cs, provedores em Application/NfseSpTax/
Validação da entrada
Application/Validators/NfseSpTaxCalculationRequestValidator.cs
Montagem a partir da tela
pages/emissao-nfse/models/emissao-rps-teste.models.ts (buildNfseSpCalculateTaxesRequest)

3. Envio à prefeitura Agente API

  1. Lista de NFs → Processar RPS pendentes ou menu Ações → Enviar nota: POST /api/local/rps/process-queued/{notaId}.
  2. Se NfeIntegration:SendToWebService = false, só gera os arquivos (não envia).
  3. Assina com o certificado ativo, envia para lotenfeasync.asmx e recebe o protocolo.
  4. Resultado → POST /api/v1/notas-fiscais/persist/send-result (gravado na nota certa pelo notaId). Erros da prefeitura são gravados em notas_fiscais.erros_envio e exibidos abaixo da linha na lista.
  5. O XML enviado fica em RpsOut\NFE_SP_SoapEnvioLoteRps_*.xml.
Montagem do XML
Infra/Mapping/EnvioLoteRpsPedidoMapper.cs (DTO → tipos XSD) e Infra/Services/XmlSerializerService.cs (escrita do XML, ordem dos elementos)
Destinatário IBS/CBS
XmlSerializerService.WriteInformacoesPessoa — grava end e email (sem eles: erros 251–253)
Persistência do resultado
LocalAgent.Api/Services/LocalAgentNotaFiscalSyncService.cs → Application/UseCases/NotasFiscais/PersistRpsSendResultUseCase.cs
Erros abaixo da linha
pages/lista-notas-fiscais/ (errosDaNota, showEventosRow)

4. Consulta do protocolo, autorização e tabela NF Agente

  1. Menu Ações → Consultar nota na prefeitura (POST /api/local/rps/status) consulta o lote pelo protocolo.
  2. Lote processado → número da NFS-e → persist/batch-status (nota fica Autorizada).
  3. Para cada nota autorizada que veio do RPS, o agente insere uma linha na tabela NF do Access (ver tabelas). Idempotente: não duplica se já existir.
  4. No log do agente: "Tabela NF do Access: NFS-e X (RPS Y) -> Inserted | AlreadyExists | RpsNotFound | Skipped".
Gatilho
LocalAgentNotaFiscalSyncService.RecordAuthorizedNotasInAccessAsync (chamado no send-result síncrono e no batch-status)
Gravação da NF
Infra/Repositories/AccessRpsRepository.Nf.cs → InsertNfFromRpsAsync

5. Pagamento Front API Agente

  1. Menu Ações → Informar pagamento (notas autorizadas).
  2. PATCH /api/v1/notas-fiscais/{id}/pagamento grava no PostgreSQL.
  3. Em seguida a tela chama PATCH /api/local/access/nf/{numero}/pagamento, que atualiza Pago, dt_pgto e valor_depositado na tabela NF. Desmarcar "pago" limpa data e valor.
  4. Se a NF não existir no Access, o pagamento continua salvo e a tela só avisa.
Tela
pages/lista-notas-fiscais/lista-notas-fiscais.ts (saveModal, syncPagamentoNfAccess)
Access
AccessRpsRepository.Nf.cs → UpdateNfPagamentoAsync; endpoint em LocalAgent.Api/Endpoints/AccessEndpoints.cs

6. Cadastro de tomadores Front API

  1. Tela Tomadores (/nfse/tomadores): busca, inclusão, edição e exclusão. Endereço completo é obrigatório (logradouro, número, bairro, código IBGE de 7 dígitos, UF, CEP).
  2. Na emissão: digitar CPF/CNPJ ou razão social sugere tomadores; CPF/CNPJ completo preenche tudo automaticamente; botão Salvar no cadastro.
  3. Armazenado no PostgreSQL, tabela tomadores (CPF/CNPJ único).
Back-end
Domain/Entities/Tomador.cs, Application/UseCases/Tomadores/, Api/Controllers/TomadoresController.cs
Front-end
pages/cadastro-tomadores/, data-access/services/tomadores-api.service.ts

7. Seleção de certificado Front Agente

  1. Tela Configurações lista os certificados do Windows (GET /api/local/certificates) e seleciona um (POST /api/local/certificates/select).
  2. O perfil é salvo em profiles.json e passa a ser usado em todas as assinaturas.
Código
Infra/Services/CertificateProvider.cs, LocalAgent.Api/Endpoints/CertificatesEndpoints.cs

Build e instalador

MicroledNF\scripts\build-onprem-installer.cmd
  • Publica API, agente e launcher, compila o Angular (baixa um Node portátil se necessário), copia para api\wwwroot, baixa o PostgreSQL portátil e gera dist\installers\Microled-NFe-AmbienteLocal-1.0.0.exe.
  • Não use -SkipPackageBuild após mudar código: ele só reempacota o dist\onprem-package antigo.
  • Não pule o PostgreSQL: o pacote é apagado antes de ser montado e o instalador sairia sem banco.
  • Migrations são aplicadas automaticamente quando a API inicia.
  • Conferência: a pasta dist\onprem-package deve ter a data/hora do build.
